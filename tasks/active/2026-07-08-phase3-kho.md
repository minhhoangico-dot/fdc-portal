## 0. THE ONE RULE (read first)

This is the chief accountant's (KTT) primary financial workspace and **live-auth verification is BLOCKED in this environment**, so the numbers must be **provably unchanged**. Phase 3 consolidates **PRESENTATION ONLY**. The two big viewmodels (`usePharmacyInventory`, `useSupplyInventory`) and every other data hook are **frozen** — reused **verbatim**. If a build step finds itself editing a Supabase query, a KPI computation, an anomaly threshold, a sort comparator, or a filter predicate — **STOP, it is out of scope.** The data-merge (`useInventoryModule(config)` unification of the two ~65%-identical hooks) is explicitly **DEFERRED** to a later live-verified phase.

## 3. Shared-primitive API

### 3.1 `src/ui/DataTable.tsx` (opus) — controlled, presentational, PURE PASSTHROUGH

Renders exactly the rows it is given, **in the given order**, with caller-supplied cell renderers. It never sorts, filters, slices, or re-derives — sorting is controlled by the viewmodel (`sortKey`/`sortDir`/`onToggleSort` come straight from `usePharmacyInventory`/`useSupplyInventory`). This purity is load-bearing for numbers-unchanged.

```ts
export interface DataTableColumn<Row> {
  key: string;
  header: ReactNode;
  align?: 'left' | 'right' | 'center';          // default 'left'
  sortKey?: string;                              // sortable iff present
  cell: (row: Row) => ReactNode;                 // caller controls all formatting
  cellClassName?: string;                        // e.g. 'hidden md:table-cell', 'tabular-nums'
  headerClassName?: string;
}
export interface DataTableProps<Row> {
  columns: DataTableColumn<Row>[];
  rows: Row[];                                    // rendered as-is, in order
  rowKey: (row: Row) => string;
  sortKey?: string;
  sortDir?: 'asc' | 'desc';
  onToggleSort?: (key: string) => void;          // wired to vm.toggleSort
  onRowClick?: (row: Row) => void;
  isRowActive?: (row: Row) => boolean;           // valuation row highlight
  emptyLabel?: ReactNode;                        // default "Không có dữ liệu."
  density?: 'comfortable' | 'compact';           // 'compact' = accounting (px-3 py-2, 13px)
  stickyHeader?: boolean;                        // default true
  className?: string;
}
```
Tokens only: `bg-card`, `text-ink-*`, `border-line`, sticky `thead` on `bg-paper`, `[font-variant-numeric:tabular-nums]` on right-aligned numeric cells, sort afflordance = `ArrowUpDown` tinted `brand-600` when active. Row hover `bg-brand-50/40`. No indigo.

export function formatCompact(value: number): string {   // matches the 7 identical copies verbatim
  if (value >= 1_000_000_000) return `${(value / 1_000_000_000).toFixed(1)} tỷ`;

}

## 4. Warehouse-switcher model (the numbers-safe core)

The two viewmodels return **near-identical shapes** (audit §4 item 1): `{ filteredInventory, uniqueCategories, uniqueWarehouses, sortKey, sortDir, toggleSort, searchQuery/setSearchQuery, filterWarehouse/…, filterCategory/…, filterStatus/…, selectedItem/setSelectedItem, anomalies, acknowledgeAnomaly, snapshotHistory, filteredSnapshotHistory, itemSnapshots, isLoading*, topMaterials, filteredValue, lastSyncDate, error, stats:{totalItems,activeAnomaliesCount,nearExpiryCount,estimatedValue} }`. Pharmacy additionally has `activeTab/setActiveTab`; supply additionally exposes raw `inventory`. The shared views consume the **common** shape.

`KhoWorkspace` instantiates **both**, enabling only the active one — identical to `app/valuation/page.tsx`:
```ts
const [warehouse, setWarehouse] = useState<'thuoc'|'vat-tu'>(fromQuery ?? 'thuoc');
const pharmacy = usePharmacyInventory({ enabled: warehouse === 'thuoc' });   // VERBATIM
const supply   = useSupplyInventory({   enabled: warehouse === 'vat-tu' });  // VERBATIM
const vm = warehouse === 'thuoc' ? pharmacy : supply;
```
Because only one hook is `enabled`, only one runs queries; the other returns empty and idle. **No dataset is ever merged.** Each warehouse's numbers therefore come from the *same unedited hook* that drives the live `/pharmacy` and `/inventory` pages → identical by construction. Switcher + active sub-tab persist to `?wh=` / `?tab=` for deep-linking and deterministic side-by-side screenshots.

Warehouse-specific asymmetries preserved (not normalized):
- **Thuốc** list columns: Mã / Tên / Kho / ĐVT / Lô SX / HSD / Trạng thái(derived) / Tồn / Đơn giá / Giá trị; status via `getDerivedPharmacyInventoryStatus` + `hasPharmacyExceptionalAnomaly` (from `lib/pharmacyInventoryPresentation`, reused verbatim) rendered through `ui/StatusBadge`.
- **Vật tư** list columns: Tên / Loại / Tồn / Đơn giá / Giá trị / Kho / TT(raw status); status via the raw-`item.status` map.
- **Thuốc** Tổng quan = shared KPI + ValueTrend + TopMaterials + anomaly preview. **Vật tư** Tổng quan = existing `OverviewTab` mounted verbatim (keeps cost-per-visit/consumption analytics + `useSupplyChart` untouched). Deliberate asymmetry this phase; full Vật tư-overview reskin defers with the data-merge.

1. **By construction**: the `enabled`-dual-hook (§4) means each warehouse renders from the *same unedited viewmodel* as the live page; `DataTable`/`ChartFrame` are pure passthrough (no sort/derive) → output is a re-skin of identical data.
2. **Side-by-side desktop diff (KTT review)** — compare to the digit:
   - `/pharmacy` ⟷ `/kho?wh=thuoc` — 4 KPIs, list `filteredValue` + row count, top-10 order/values, value-trend endpoints, active-anomaly count.
   - `/inventory` ⟷ `/kho?wh=vat-tu` — KPIs, list total-by-filter, anomaly count; Tiêu thụ/Nhập xuất/Kiểm kê tabs are the verbatim components (byte-identical).

4. **Filter/sort parity**: toggling warehouse/category/status/search/sort in `/kho` produces the same `filteredInventory` as the legacy page (same hook, same predicates) — spot-check a filtered `filteredValue`.
5. `npm run lint` (tsc --noEmit) 0 errors; `npm run build`; `check:bundle`; `check:pwa`; `check:auth-smoke` (likely blocked in this env — document if unrunnable). Screenshots (Thuốc/Vật tư × each sub-tab, desktop) into `tasks/handoffs/`.
